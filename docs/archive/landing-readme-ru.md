# Solo + AI Berlin — лендинг и подключение оплаты

## Что готово

Англоязычный адаптивный лендинг `index.html`: позиционирование, расписание, история организатора, €59 за пилот, правила отбора и возврата, FAQ, трёхшаговая анкета. Откройте файл в браузере: он работает без сборки, CDN, внешних шрифтов и сторонней графики.

По умолчанию это **PREVIEW**. Анкета проверяет поля, позволяет переходить между шагами и показывает объяснение будущей оплаты. Она ничего не отправляет, не сохраняет ответы в браузерное хранилище и не принимает деньги. При закрытии/перезагрузке страницы введённое теряется. Превью не является опубликованным сайтом.

В комплекте также есть необязательный сервер `server.py` на стандартной библиотеке Python. Он позволяет сохранить заявку в SQLite и затем отправить участника на Stripe Payment Link. Сервер не нуждается в Stripe secret API key и не умеет инициировать платежи или возвраты самостоятельно: платёж проходит на Stripe, возврат делает организатор в Stripe Dashboard.

Юридические файлы специально отмечены как черновики. Сервер не разрешит включить `APP_MODE=live`, пока они содержат предусмотренные маркеры незаполненных полей и пока `LEGAL_READY` не установлен в `true`. Эта проверка не заменяет юридическую проверку: она лишь мешает случайно включить оплату с незавершёнными страницами.

## Запуск локального превью

Нужен Python 3.10 или новее. Библиотеки для самого сервера устанавливать не требуется.

```bash
cd solo-ai-berlin
python server.py
```

Откройте `http://localhost:8080`. Это сервер для локальной проверки. **Не используйте его как публичный production-сервер.**

Просто открыть `index.html` также достаточно для просмотра дизайна и анкеты.

## Как подключается Stripe

1. В собственном Stripe создайте **Payment Link** для разовой оплаты **EUR 59.00 total**, с фиксированным количеством 1. Не добавляйте подписку, изменение количества, дополнительные продукты, промокоды или налог поверх €59. Налоговые настройки должны соответствовать реальному оператору и сохранять объявленную итоговую цену. Отключите автоматическую локализацию валюты, чтобы платёж приходил в EUR; сервер ожидает ровно 5900 евроцентов.
2. Для пилота проще оставить немедленно подтверждаемые способы оплаты. Если включаете отложенные способы, учтите дедлайн: завершение Checkout ещё не обязательно означает поступление оплаты. Сервер обрабатывает delayed-payment события, но организатор должен сверять платежи, которые завершились поздно.
3. Укажите возврат после Checkout на `https://YOUR-DOMAIN.example/?checkout=returned`. Эта страница намеренно не говорит «вы приняты» или «оплата подтверждена» только на основании URL. Настройте квитанции Stripe отдельно.
4. Создайте webhook endpoint `https://YOUR-DOMAIN.example/api/stripe-webhook` на события:
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`
   - `checkout.session.async_payment_failed`
5. Скопируйте `.env.example` в `.env` и укажите реальный домен, email, публичный Payment Link, идентификатор `plink_...` и endpoint signing secret `whsec_...`. Это отдельный секрет подписи webhook, не `sk_...` API key. **Никогда не вставляйте секреты в HTML, публичный репозиторий или сообщения посетителю.**
6. Завершите privacy notice, imprint и условия, включая фактического продавца, налогообложение, данные обработки заявок, применимые права отказа и реквизиты. Затем выставьте `LEGAL_READY=true`.
7. Сначала используйте тестовый Payment Link и `STRIPE_LIVEMODE=false`. `APP_MODE=live` включает настоящий поток сохранения анкеты, но при false сервер показывает баннер **TEST CHECKOUT**. Используйте только вымышленные тестовые данные.
8. После проверки полного сценария замените настройки на live-ссылку, её `plink_...`, live endpoint secret и выставьте `STRIPE_LIVEMODE=true`. Откройте приём только на HTTPS и после проверки сайта на собственном домене.

### Что делает поток

```
Анкета → POST /api/applications
       → проверка полей и согласований на сервере
       → сохранение в SQLite
       → Stripe URL с client_reference_id=app_...
       → Stripe Checkout
       → подписанный webhook
       → отдельная отметка о платеже
       → ручное рассмотрение, подтверждение / возврат
```

В Stripe отправляется случайный идентификатор заявки, не текст ответов. Повторная попытка отправки с тем же ключом не создаёт вторую заявку. Повторно доставленные webhook-события не дублируются. Проверяются подпись, время подписи, test/live-режим, Payment Link, сумма и валюта. Возврат на лендинг сам по себе не изменяет платёжный статус.

Неправильная сумма, неопознанная заявка, возможный повторный платёж и платёж после дедлайна помечаются для ручной проверки. Прямая публичная Payment Link остаётся доступной тому, кто её знает: не публикуйте её вместо формы. Если кто-то оплатил без заявки, свяжитесь с плательщиком или верните деньги; автоматического места у него нет.

**Важные пределы:** код не отправляет email, не принимает решения об отборе, не резервирует 12 мест атомарно и не выполняет возвраты. Он также не синхронизирует последующие возвраты, споры и chargebacks. Финансовый источник истины — Stripe Dashboard. Перед подтверждением каждого участника сверяйте фактический платёж, доступность места и выполненные возвраты. Отбор ведите самостоятельно; массовую рассылку/запуск и возвраты на дедлайн запускайте вручную.

Дедлайн блокирует новые отправки формы, но **не деактивирует Payment Link в Stripe**. Закройте ссылку вручную при завершении набора, достижении подходящего состава или наступлении дедлайна. Не принимайте сверхлимитные платежи без необходимости. На странице обещан полный возврат, если место предложить невозможно.

## Где хранить и размещать

Для стандартного backend нужен host с Python, HTTPS и **постоянным приватным диском**. SQLite нельзя использовать в эфемерной файловой системе serverless-функций как надёжное хранилище заявок. Статический HTML можно размещать отдельно, но тогда потребуется адаптировать `applicationEndpoint`, правила same-origin/CORS и CSP; это не подключение одной ссылки.

Для небольшого пилота пример production-запуска за HTTPS reverse proxy:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install gunicorn
gunicorn --workers 1 --threads 4 --bind 127.0.0.1:8080 server:application
```

Команда с Gunicorn приведена как инструкция для вашего хостинга; в комплект не входит установленный production-сервер. Задайте `DATABASE_PATH` на приватный постоянный диск, защитите аккаунт и резервные копии, настройте HTTPS, лимиты запросов на proxy и мониторинг ошибок webhook. Простая встроенная защита от частых запросов рассчитана на малый пилот, не заменяет полноценную защиту публичного сервиса. Если reverse proxy передаёт один адрес для всех посетителей, настройте доверенную обработку адресов/лимиты до публичного запуска; не доверяйте произвольному `X-Forwarded-For`.

Не размещайте весь архив как общедоступную директорию со включённым listing. WSGI-приложение отдаёт только явно разрешённые страницы и не публикует `.env`, базу или Python-код.

## Просмотр заявок

На сервере:

```bash
python manage.py summary
umask 077
python manage.py export > applications-private.jsonl
```

Выгрузка содержит персональные данные: держите её приватно. Отдельно организуйте сроки удаления неоплаченных/отклонённых заявок, доступ к базе и резервным копиям, а также законное хранение финансовых записей. Удаление и рассылки не автоматизированы.

## Что доделать до публикации

Самостоятельный HTML уже пригоден для просмотра и редактирования. До публичного сбора нужны ваш домен/хостинг, актуальные реквизиты продавца и контакты, законченные юридические страницы, настроенная Stripe-ссылка, webhook и проверенный тестовый платёж. До начала встреч нужно подтвердить площадку на обе даты и уложиться в обещанный deadline. Оплата помещения, создание реального Stripe-продукта и публикация сайта в этом комплекте не производились.
